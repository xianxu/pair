# Mock-to-real development

Start the app's own development command in any web stack, then run `couch mock serve mocks/ --real http://localhost:3000`. Open its printed front URL. The front does not start or stop the app and needs no Couch supervisor. The [Go worked sample](../examples/mock-to-real/README.md) combines two real screens, one mock and an independent real backend.

One `screens.json` declares `version:1` and a `screens` array of unique `id`, canonical `route`, version-relative HTML `mock` path and explicit `state` (`real` or `mock`). Root uses `index.html`. Real routes proxy to the fixed loopback app; mock routes open the selected version with visible MOCK/progress. Version aliases use that same catalogue, so a promoted screen opens its canonical app route. Queries/fragments retain browser semantics. Real responses and errors pass through unchanged; errors never cause mock fallback.

`mockserve/screens.go` owns parsing, indexed lookup and reporting; `front_route.go` owns pure routing; `front.go` owns HTTP and connection lifetime. Existing project/scan/revision owners publish catalogue/health/revision together. Every declared mock document must exist exactly: startup refuses or runtime shows repair, never index fallback. Standalone mode keeps its original behavior. Catalogue cap is256 KiB/256 screens, within existing project caps; HTTP never exposes it and Couch never rewrites it. The development front still requires a valid mock project when all screens are real; keep versions as design history.

Cross-boundary SPA links must load a full document; client-only navigation cannot reach a generic HTTP front. Reserved mock/internal/private paths terminate locally; other requests, including APIs/assets/streaming/WebSockets, go to the fixed app. The catalogue describes navigation, not authorization. --real accepts HTTP loopback with an explicit port and no credentials/path/query; localhost is pinned to IPv4, so use an explicit IPv6 loopback URL for an IPv6-only app. Progress is guaranteed on mock pages and in the console; real HTML gets no injected chrome.

The front caps active proxy/upgrade requests at64. Cancellation closes upgraded connections and idle transport and joins requests/scanner/listener/project ownership, leaving the app running. Hybrid streaming has no total write timeout; standalone mock mode keeps its existing timeout. Header/dial budgets and bounded stream buffers remain. No app supervisor, extra watcher, cache family or request retry is added.

Production is the app's own stack/build. `couch mock check mocks/` needs only screens.json and prints progress/missing IDs/routes. Missing implementation is success; invalid input is an error. It writes no files, builds nothing and cannot certify arbitrary bundles. Each framework implements plain **Not implemented yet** pages with a way back and visibly marked links, excluding mock code, fixtures and badges. Strict means no mock content ships; partial implementation does not refuse the build.

The Go sample's own build emits a minimal production screen projection and compiles only real app code; fixture contracts compare independent real HTTP data against shared fixture shapes. Root `mocktemplate/template_test.go` explicitly runs nested tests/builds and actual host/app conformance. Mockserve covers stateful upstreams, upgrade/stream shutdown, strict document repair and counted hot paths. WEBCAST_LIVE_CHROME=1 enables private headless hybrid navigation qualification; suppressing delivered progress must make its assertion fail.
