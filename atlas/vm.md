# VM runner

`pair vm run` is the generic command runner in `cmd/internal/vmcmd/`. The streaming route enters `RunCLI`; `Run` advances the pure `RunState` and executes its requested effects through one per-run `Runtime`. `hostRuntime` owns machine files/claims and `VMDriver` owns Tart transport/child handles. The native adapter uses the account database home rather than inherited `HOME`/`TART_HOME`. Linux and other platforms refuse native execution.

The private machine root is `<native-home>/.tart/pair-runner/`. Its qualified `image.json` pins the local image name, base digest and tool evidence. Stable kernel positions under `positions/train` and `positions/adhoc` remain held through collection, stop/join and release. Each direct subprocess stays unreaped through its final group signal; signalling is retired before Wait, with observation-only confirmation afterward. A launching claim precedes snapshot subprocesses and clone/start; the child PID/start identity is published after launch. Secondary probes/exec/export/stop/deletion persist a blocking `cleanup-unknown` marker before their effect and restore prior recovery authority only after confirmed completion. Unresolved startup, an unconfirmed subprocess group, or a VM without an owned claim prevents reuse. Positive recovery needs the exact prior leader generation and its whole group gone and the VM stopped; unknown evidence refuses. A retained `cleanup-unknown` stage requires inspection/repair rather than automatic recovery. The interactive `pair-test` VM is outside this lifecycle.

Snapshots enumerate tracked paths once, retain current tracked bytes/deletions and omit untracked/ignored runtime inputs. Independent shallow Git metadata contains the selected HEAD commit/tree/blob closure, with replacement interpretation and lazy remote fetch disabled. The 100,000-path / 2 GiB budget includes metadata reservation; binary pack transfer is capped before current files are overlaid. File clone falls back to bounded copy only for cross-volume/unsupported filesystems. Reports include metadata, cloned and copied bytes.

Tart receives only the owned read-only input share. Results stay in a fresh guest-local directory; bounded guest-agent export admits the bootstrap manifest, status and up to eight diagnostic logs. No guest-writable host directory is exposed. The embedded bootstrap copies the workspace into guest-local storage and supplies a clean environment, private HOME/TMP/XDG/Pair/Couch/socket/queue roots, and literal command argv. Host credentials/session stores and the live checkout are not shared. Ordinary runs use no host installation or image refresh operation.

The execution envelope is **timeout N + cleanup up to 10 s** (default N=20m). Acquisition through execution shares N; collection, stop/join and release share a detached ten-second budget. Boot readiness is bounded to two minutes within execution. Cleanup expiry closes local handles but retains durable occupancy and VM/input files; inspect the named VM before reuse. A command failure survives subsequent collection/cleanup errors. A successful command with unconfirmed result or cleanup returns infrastructure failure.

Each artifact bundle has host-owned `run.log`, separate `stdout.log`/`stderr.log`, `result.json`, and an unshared `guest/` export directory. All three log writers charge one shared budget; export and terminal metadata reserve their bounded capacity up front, keeping the combined host-write ceiling at 256 MiB. The manifest admits only the bootstrap fixed catalog, preserves raw additive metadata and refuses duplicates/invalid types, changed sizes, missing members and symlinked guest paths. Final validation follows VM stop/join, rejecting unexpected symlinks, special files or changed status. Retained results preserve image download provenance and historical launch PID/start identity plus whether guest execution was requested, distinguishing a startup timeout from earlier preparation. Default bundles are retained under the lane (eight bundles / 4 GiB); only completed ordinary bundles are pruned. A fresh explicit destination is caller-owned. Guest diagnostics are separately bounded by the embedded bootstrap. Native VM-disk peak and real transport/isolation behavior remain qualification work; fake tests do not establish real Tart isolation.

`pair vm provision --checkout /absolute/repo` prepares a fresh pinned base through the same ad-hoc position, startup claim and owned subprocess lifetime. The guest-only script installs checksum-pinned vendor tools and rejects physical hosts; its lock retains archive provenance and the official Zellij binary digest. Guest qualification checks isolated roots, the read-only share, independent Git, CLT, PTY and native tools before stopped-image sealing. Activation follows validated host evidence, source cleanup and log closure under the original position and ten-second cleanup budget. Failed activation never replaces the active manifest. All managed candidate images, including unpublished ones, count toward the two-image retention ceiling; refresh refuses at the ceiling for explicit inspection, and never automatically prunes cached images or pair-test.
