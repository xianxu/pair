# VM runner

`pair vm run` is the generic command runner in `cmd/internal/vmcmd/`. The streaming route enters `RunCLI`; `Run` advances the pure `RunState` and executes its requested effects through one per-run `Runtime`. `hostRuntime` owns machine files/claims and `VMDriver` owns Tart transport/child handles. The native adapter uses the account database home rather than inherited `HOME`/`TART_HOME`. Linux and other platforms refuse native execution.

The private machine root is `<native-home>/.tart/pair-runner/`. Its qualified `image.json` pins the local image name, base digest and tool evidence. Stable kernel positions under `positions/train` and `positions/adhoc` remain held through collection, stop/join and release. A launching claim precedes clone/start; the child PID/start identity is published after launch. Unresolved startup, an unconfirmed subprocess group, or a VM without an owned claim prevents reuse. Positive recovery needs the exact prior process generation gone and the VM stopped; unknown evidence refuses. The interactive `pair-test` VM is outside this lifecycle.

Snapshots enumerate tracked paths once, retain current tracked bytes/deletions and omit untracked/ignored runtime inputs. Independent shallow Git metadata contains the selected HEAD commit/tree/blob closure, with replacement interpretation and lazy remote fetch disabled. The 100,000-path / 2 GiB budget includes metadata reservation; binary pack transfer is capped before current files are overlaid. File clone falls back to bounded copy only for cross-volume/unsupported filesystems. Reports include metadata, cloned and copied bytes.

Tart receives only the owned read-only input and writable guest-result shares. The embedded bootstrap copies the workspace into guest-local storage and supplies a clean environment, private HOME/TMP/XDG/Pair/Couch/socket/queue roots, and literal command argv. Host credentials/session stores and the live checkout are not shared. Ordinary runs use no host installation or image refresh operation.

The execution envelope is **timeout N + cleanup up to 10 s** (default N=20m). Acquisition through execution shares N; collection, stop/join and release share a detached ten-second budget. Boot readiness is bounded to two minutes within execution. Cleanup expiry closes local handles but retains durable occupancy and VM/input files; inspect the named VM before reuse. A command failure survives subsequent collection/cleanup errors. A successful command with unconfirmed result or cleanup returns infrastructure failure.

Each artifact bundle has host-owned `run.log`/`result.json` and a separately shared `guest/` directory. Collection rejects symlinks, special files, more than 100,000 entries and over 256 MiB. Default bundles are retained under the lane (eight bundles / 4 GiB); only completed ordinary bundles are pruned. A fresh explicit destination is caller-owned. Guest diagnostics are separately bounded by the embedded bootstrap. Peak native storage and enforcement behavior remain qualification work; fake tests do not establish real Tart isolation.
